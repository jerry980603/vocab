# 補一批單字進字庫

這個專案是一個台灣高中生自用的學測單字練習 App。他的讀書計畫每天要學數十個新字，
但**字庫的編寫速度是整個計畫的瓶頸**——他沒有字就沒得練。你的工作就是穩定地把
官方詞彙表裡「還沒編寫例句」的字，一批一批補成完整詞條。

品質比數量重要。使用者明確排過優先序：

1. **中文釋義最重要**——要正式、要準確、一字多義要收齊
2. **例句以「用法正確」為底線**——搭配詞與句型必須對，文采不重要
3. 數量最後

## 流程

### 1. 先看目前進度

```bash
python .claude/skills/add-words/scripts/todo.py
```

會印出每個分級「已寫幾個／還缺幾個」。接著挑要做的分級，列出待補清單：

```bash
python .claude/skills/add-words/scripts/todo.py 3 130
```

輸出的每一行是「單字　官方詞性」。**官方詞性直接照抄，不要自己判斷**——
那是大考中心詞彙表的原始標註，是這個專案唯一完全可信的欄位。

如果使用者沒指定分級，看 `CLAUDE.md` 最上面的「下一批要做」。
沒有特別指示時，優先做第 3、4 級——那是學測的主要得分區。

### 2. 挑字

一批做 100～130 個。從待補清單裡挑，但**跳過學測不會考的冷僻具體名詞**
（kangaroo、spaghetti、zipper、doughnut 這類）。優先選：

- 動詞與形容詞（填空題的主力）
- 抽象名詞（achievement、conclusion、evidence…）
- 一字多義、多詞性的字（這種最值得練，App 可以讓他分別練不同意思）

### 3. 查證每個多義字

**這一步不能省，它是這個 skill 存在的主要理由。**

凡是官方標了兩個以上詞性、或你直覺覺得有多個常考意思的字，
先開 `https://www.ldoceonline.com/dictionary/該字` 查證（WebFetch 可以抓，
劍橋和大考中心的網站會擋）。你要從朗文拿到兩樣東西：

- **義項清單**——它有哪幾個意思，中文釋義要對應到其中某一個 sense
- **文法句型**——例如 `assist somebody in doing something`、`grasp what/how`

單一詞性又意思單純的字（elderly、humid、cheerful）可以直接寫，風險低。

**踩過的實例，用來理解為什麼要查：**

`engage` 曾被寫成「v. 使訂婚」，例句用 `They got engaged`。這是錯的——
朗文的動詞條目根本沒有訂婚這個意思，`got engaged` 用的是形容詞 `engaged`。
教訓是：**不要把某個變化形的慣用法，當成原形動詞的義項。**

### 4. 寫進新檔案

**開新檔**（`w8.js`、`w9.js`…），不要用腳本插進既有檔案。原因見最後一節。

格式定義在 `data/bank.js`：

```
@abandon|4
=v.|拋棄；遺棄
.The crew had to {{abandon}} the sinking ship as it began to tilt.|船身開始傾斜時，船員們只好棄船逃生。
.She would never {{abandon}} a close friend who was in serious trouble.|她絕不會拋下陷入嚴重麻煩的好朋友。
=v.|放棄（計畫、想法）
.He {{abandoned}} his plan to study abroad after his father fell ill.|父親病倒後，他放棄了出國念書的計畫。
```

- `@單字|分級` —— 分級是官方的 1～6。查無此字才標 `0`（要有理由）。片語不標分級。
- `=詞性|中文意思` —— 一個字有幾個常考意思就寫幾個 `=`
- `.英文|中文` —— 要挖空的字用 `{{ }}` 包起來，裡面放**句子裡實際出現的形式**
  （`{{abandoned}}`、`{{looking forward to}}`），系統直接拿它比對答案

寫完在 `index.html` 與 `sw.js` 各加一行載入新檔，並把 `sw.js` 的 `CACHE`
版本號 +1（不然使用者手機會拿到舊快取）。

### 5. 跑驗收

```bash
python .claude/skills/add-words/scripts/check.py w8.js
```

必須看到「✅ 全部通過」才算完成。它會檢查檔案結構、完整性、詞性覆蓋、
句子長度、中文純度。舊批次的已知問題不會擋你。

**接著做三項人工檢查**（使用者明確要求，自動腳本抓不到）：

1. **有沒有漏掉易考的多義字？**
   腳本只比對得到「詞性」層。同一個詞性底下可能有多個常考意思，
   要逐條對照朗文問「這個 sense 學測會不會考」。
   踩過：`loose` 漏了「掙脫的」、`solid` 漏了「純的；實心的」、
   `bitter` 差點只寫「味苦的」而漏掉「憤恨的」與「嚴寒的」。

2. **中文解釋是否精闢正確？**
   每個 `=` 都要對應到朗文的某一個 sense，用正式的字典體釋義，不要口語。

3. **句子的用法、語法、文法是否正確？**
   逐句重讀，特別留意冠詞、單複數、時態一致，以及不自然的搭配。
   踩過：`leave a safe job for art` 應為 `for a career in art`。

判定罕考而刻意不收的義項，要寫進 `CLAUDE.md` 的「刻意不收」那一節，
並同步更新 `check.py` 裡的 `SKIP_POS`，否則下次驗收會一直報同一個缺漏。

### 6. 更新進度

回 `CLAUDE.md` 更新「字庫進度」那一段：總數、新檔案的字數、下一批要做什麼。
**這一步很重要**——使用者每天開新對話，全靠這份文件接手。

## 寫例句的規則

**句子長度一律 10～14 個英文單字。** 這是硬性要求，驗收腳本會擋。

太短的句子沒有情境線索。`The surgeon performed the operation.` 幾乎沒有
給出任何能幫他回想起 `perform` 的東西，他只能靠中文提示硬背，
整個 App 賴以運作的情境記憶法就失效了。句子要提供**足以回想出目標字的上下文**，
加上原因、結果、時間或對比都可以。

其餘規則：

- **每個 `=` 至少 2 句例句**，練習時會輪流出現。同一個字只在一句話裡看過，
  換個句子就認不得了——這是情境記憶法最大的弱點，多句輪替是解法。
  次要或冷門的義項可以只給 1 句。
- 英文要**道地而正式**：完整句、正確搭配詞，避免口語縮寫與俚語。
  不確定某個搭配自不自然，回去查朗文。
- **句子裡其他的字要比目標字簡單**，不要用更難的字去解釋難字。
- 中文翻譯用**台灣用語的繁體中文**，標點用全形（，。？！），不可出現簡體字。
  中文裡不要混英文字（踩過兩次：`整座村莊completely被雪掩埋`、`偏遠的山village`）。
  例外：釋義裡用全形括號標搭配詞是可以的，例如「說明；解釋（account for）」。
- 中文釋義比照學測 7000 單字表的常見譯法，多個意思用全形分號 `；` 隔開。
- 內容裡不要出現 `|`，那是欄位分隔符。

## ⚠ 用腳本批次改資料檔的陷阱（踩過一次，代價很大）

每個資料檔是一整個 JS 樣板字串，開頭 `addWords(\`` 、結尾 `` `); ``。

如果腳本用「一直讀到下一個 `@` 或空行為止」的方式抓某個字的區塊，
遇到**檔案最後一個字**時會把結尾的 `` `); `` 也吃進去，新內容被插到結束符號後面，
整個檔語法錯誤 → `addWords()` 不執行 → **那個檔的字全部消失**。

症狀是 console 出現 `SyntaxError: Unexpected token '='`，而字數大幅減少。
`check.py` 的「A 檔案結構」就是在擋這個。**這也是為什麼新批次一律開新檔。**

## 本機驗證

`.claude/launch.json` 已設定好，用 preview_start 啟動名為 `vocab` 的設定
（`python -m http.server 8712`）。改完資料檔後瀏覽器可能拿到快取的舊版，
先用 `fetch(檔名, {cache:"reload"})` 強制重抓再 reload，否則你會看到改動沒生效。

在 console 確認沒有紅字，並且 `WORD_BANK.length` 有如預期增加。
**數字變少就是資料檔壞了**，回去看上一節。
